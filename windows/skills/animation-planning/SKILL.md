# 动画分析与体积优先编排

先分析再分层/生图。默认目标是在动作清楚、文案可读、循环自然的前提下，产物体积尽可能小。档位代表所需的动画复杂度与帧预算，不是画质承诺，也不是越高越好。未经观察不能宣称已自动识别内容或测得GIF大小。

## 识别元素与动作

查看用户参考图或当前项目snapshot，记录原图宽高。识别主体、背景、按钮、金额/标题、Logo、装饰、出入口与遮挡关系。已有项目先读取已有图层、FPS和时长。只为与目标有关的元素规划运动，不要求每个元素都动。

| 元素 | 优先考虑 | 保持质量与控制体积 |
| --- | --- | --- |
| 按钮/领取入口 | 小幅中心缩放，通常约1–1.04倍 | 视觉中心固定；文字完整，不做大位移或多次弹跳 |
| 货币金额 | 出现货币金额时，考虑一次局部窄光带扫光 | 保留数字、货币符号和单位，高光只裁切在金额前景Alpha内，不照亮整块底板；结合焦点、可读性与体积预算决定是否采用 |
| 短标题/Logo | 单次窄光带扫光，必要时轻微强调 | 避免整块底板或全图变色 |
| 金币/彩带/装饰 | 少量轻摆、局部漂浮；用户需要时才抛洒 | 优先复用纹理，减少粒子数量、运动面积和轨迹跨度 |
| 角色/主体 | 有意义的小幅呼吸或摆动 | 非动作焦点时静止；复杂表情/肢体动作才考虑序列帧 |
| 账单/出纸槽/揭示区域 | 固定形状遮罩内移动内容 | 用mask-effect实现遮挡，不为遮罩生图，不用全幅画面滚动 |
| 背景/长文案/规则说明 | 通常静止 | 保留阅读时间；不添加无需求的全图闪烁、缩放或粒子雨 |

货币金额识别：留意带货币符号或单位的金额（如R$542、¥888、1.064.000đ），以及在奖励/价格上下文中使用K等缩写的金额。不要把日期、编号、普通计数或品牌中的数字误认作金额。识别到金额后将“金额扫光”加入候选，而非强制添加；优先强调主要金额，避免多个金额同时扫光造成干扰。若采用，按[扫光技能](../effect/references/sweep.md)复用或建立独立金额图层，保持字符孔洞透明，不改变数值和货币含义；不能只因存在金额就增加档位、时长或FPS。用户明确指定其他动作时，未经其要求不额外叠加金额扫光。

无明确动作要求：主动选最有意义的1–2个局部焦点，通常为按钮缩放、金额/标题扫光。没有按钮或短文字时选择合理的小区域动作，不凭空添加按钮/文字，也不生硬套用模板。
有明确动作要求：优先完成指定动作，不改成更省空间但不符合需求的动作；仍可减少无关装饰。用户指定时长/FPS/文件上限时优先遵守；若与现有能力冲突，说明具体冲突，不静默替换。

## 体积风险与分档

同时观察：W×H、照片/渐变/细碎纹理与有效颜色复杂度、运动覆盖范围、变化速度、独立运动元素数量、总帧数。颜色鲜艳不一定颜色复杂：纯色块与多色照片/渐变要区分。大而静止的背景与全幅连续变化也不同。

内部相对预算可用W×H×N比较，N=duration×FPS；这是未压缩采样工作量，不是GIF字节数。再结合运动区域占比与色彩/纹理复杂度判断风险。不能由尺寸或色数推算确定的KB/MB，也不能承诺具体压缩率。

| 档位 | 参数起点（非强制预设） | 适用与编排 |
| --- | --- | --- |
| 标准 | **1秒、12FPS、12帧** | 默认优先。局部按钮缩放、文字扫光等简单强调，最多1–2个焦点，其余静止。大尺寸、多色照片、鲜艳渐变或纹理丰富素材一般用此档。 |
| 精细 | 约1–1.5秒、15–18FPS | 仅当标准方案实际出现运动不连贯、动作阶段不清晰或阅读/停顿不足时使用；少量错峰动作，不扩大无关运动区域。 |
| 极致 | 约1.5–2秒、20–24FPS | 用于明确要求的快速旋转、复杂轨迹或多个必要动作阶段；只在较低档不能达成视觉目标时选择。确需完整动作才延长至3秒。 |

以上为分析起点，不是按素材尺寸硬套的规则。大尺寸可参考像素面积≥50万，或较长边≥1000像素作为风险提醒；不是导入限制或自动降质门槛。画面简单、色彩少、尺寸小也先看标准是否够用，不能因此自动选精细或极致。

不应为了看起来高级而增加时长、帧率或装饰，也不应为了小文件把必要快速动作压到明显跳动。若标准12FPS已清晰流畅就保留；提高FPS必须有与动作速度/幅度对应的理由。慢而小的动作可低于12FPS或更短，满足质量即可。当前工具范围1–24FPS、0.5–3秒；用户有更高要求时明确能力边界。

## 编排与帧数

先确定核心动作及循环周期，再分配阶段。可并行的局部动作不累计成更长动画；需要先后顺序的动作才延长。默认标准1秒循环可让按钮缓慢放大回落、扫光在中间阶段掠过，首尾无高光、姿态衔接。不要为填满时长重复动作。

选定FPS后取整数N≈期望秒数×FPS，约束ceil(0.5×FPS)≤N≤3×FPS，最终duration=N/FPS；时间轴0…N−1。例如标准1秒×12FPS=12帧（0…11），精细1.2秒×15FPS=18帧，极致1.5秒×24FPS=36帧。总帧数不等于关键帧数量；每段仅设有意义的稀疏转折点，扫光起止也从本次阶段计算，不沿用71帧模板。

只分离真正需要独立运动/遮挡的内容。空间互不连接的元素可合成同一张纯色图集，MCP分离成独立素材，全部处理完成后统一导入。普通位移/缩放/旋转与扫光不烘焙成序列帧，相关能力见[动画执行](../animation-builder/references/animate.md)、[扫光](../effect/references/sweep.md)、[遮罩](../mask-effect/SKILL.md)。

## 执行与反馈

向用户简短给出：识别到的主要元素→所选动作与静止区域→档位、时长、FPS、总帧数→选择理由。无需罗列所有备选方案或额外确认，直接执行。create显式传fps/duration；已有项目仅改颜色/素材时保留原节奏，不无故重编。

预览检查文字/金额可读、边缘干净、运动连贯、遮挡正确、循环无突跳。标准达标就停止，不为更高档重复生图。若不达标，先缩小位移幅度/旋转速度、调整阶段与缓动；确有需要才提升FPS/延长周期。控制体积时优先移除无关动画、缩小变化范围、减少粒子，其次在质量允许范围减少FPS/时长；不删除用户要求的动作，不牺牲文案阅读，不擅自缩小输出尺寸。

GIF实际大小只能在编码后确认。导出仍由用户在面板手动操作，不为测量体积而自动导出或批量试编码。用户手动导出后有文件/实际字节数时才报告真实体积；超过其上限则基于实际文件与预览作有针对性的调整建议，压缩选项由用户在导出面板选择。未导出时只报告体积风险与预算，不能把估计写成测量值。
